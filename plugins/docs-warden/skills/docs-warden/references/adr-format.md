# Decision records: format and the immutability rule

A decision record answers **why**. `CONVENTIONS.md` answers **what we do now**. If
you find yourself writing a date into `CONVENTIONS.md`, you wanted a decision
record.

## Filename

`docs/decisions/DEC-NNNN-short-slug.md`

Four digits, zero-padded, never reused. `DEC-0007-use-proxmox-for-onprem.md`.

## Front matter

```yaml
---
id: DEC-0007
title: Use Proxmox for on-prem virtualization
status: accepted        # proposed | accepted | rejected
date: 2026-09-01
deciders: [rex]
supersedes: []          # e.g. [DEC-0003]
tags: []
---
```

`status` has exactly three values. There is no `superseded` status — see below.

## Body sections, in this order

1. **Context and problem statement** — what forced a decision. Someone who was not
   there must be able to follow it.
2. **Decision drivers** — the constraints that actually mattered.
3. **Considered options** — every option seriously weighed, including the one you
   picked. One option means you did not decide, you rationalized.
4. **Decision outcome** — what was chosen, and why that one.
5. **Consequences** — split into good and bad. A record with no bad consequences is
   not finished.
6. **Gaps accepted** — what this knowingly does not solve. This is the section
   future readers need most and the one most often skipped.
7. **Links** — ticket, PR, related records.

## The immutability rule

**Once `status: accepted`, the file is never edited. Not one word. Not even the
status field.**

This is not a style preference. The value of the log is that it records what was
believed at the time. A record you can quietly revise is a record nobody can trust
as evidence, which defeats the point of keeping one.

**To reverse a decision**, write a *new* record whose front matter says
`supersedes: [DEC-0003]`. `DEC-0003` stays exactly as it was, forever.

`adr_index.py` computes "Superseded by DEC-0012" for the index by reading the
*newer* file's `supersedes` list. The superseded status is derived, never stored —
that is precisely how the old file stays untouched.

`audit.py` enforces this by reading `git log` for the record's path, oldest first,
finding the commit that set `status: accepted`, and failing if any commit touched
the file after it. It deliberately does not use `--follow`: that flag drops
commits when combined with `--reverse`, and its rename detection traces a
scaffolded record's history back into the template it was copied from. One
consequence: a record renamed after acceptance loses the history before the
rename, so that edit goes unseen.

Two consequences worth stating plainly:

- A typo in an accepted record stays. Fix it in the superseding record.
- Marking something `accepted` is a real commitment. Leave it `proposed` while it
  is still being argued.

## The index

`adr_index.py` writes `docs/DECISIONS.md` -- the single source, with the full
table -- and `docs/decisions/README.md`, a short pointer to it. Both start with:

```text
<!-- GENERATED by docs-warden - do not edit -->
```

`docs/DECISIONS.md`'s table is newest first: ID, Title, Status, Date,
Supersedes / Superseded-by, with a one-line footer explaining how to add a
record. `docs/decisions/README.md` carries no table and no record count --
just a sentence and a link to `../DECISIONS.md`, so it does not duplicate the
index or churn on every new decision.

The script is idempotent. Running it twice must produce no diff on the second run;
CI relies on that to detect a hand edit.

## Migrating a monolithic decision log

Some repos have one hand-written file with `DEC-NNN` entries in it. Offer to split
it into one file per entry, preserving the original IDs and dates. **Ask first**,
and show the mapping before writing anything — the IDs are referenced from
elsewhere and renumbering them silently breaks those links.
