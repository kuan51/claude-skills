# ciso CMMC module: verbatim federal requirements at three levels

Design record for `plugins/ciso/skills/cmmc/` (ciso 1.1.4). It replaces the retired 2026-07-31
superpowers spec, which had no plan and described work already implemented. Fabflows format.

## Behaviour

`ciso:register` offers CMMC with three independent control sets, read from 32 CFR Part 170 via
the eCFR API:

| Tier | Requirements | Source | Validated by |
|---|---|---|---|
| `level1` | 15 | 48 CFR 52.204-21(b)(1) | annual self-assessment and SPRS affirmation |
| `level2` | 110 | NIST SP 800-171 Revision 2 | C3PAO certification, or self-assessment for some programs |
| `level3` | 24 | selected from NIST SP 800-172 (Feb 2021) | DCMA DIBCAC |

Level 3 presupposes Level 2, so `references/register.md` instructs registering both and
`references/invariants.md` names a `level3`-only registration as the most misleading state.

The module ships verbatim requirement text: `sourceAuthority: "publisher-verbatim"`, a value no
other module uses, because NIST publications and eCFR regulations are US Government works not
subject to copyright. Here `topicSummary` is authoritative and `topicLabel` is the module's own
shorthand, the reverse of every other module.

The module has no `lib/` code and no `SKILL.md`: it is `controls/level{1,2,3}.v32cfr170.structure.json`,
`references/{register,interview,roadmap,invariants}.md`, a catalog entry and
`test/cmmc-structure.test.js`. The core needed no changes.

## Check

```bash
node --test "plugins/ciso/test/cmmc-structure.test.js"
```

Passes as part of the 295-test ciso suite at the time of writing. Observable results the test
asserts: every Level 2 family contains exactly the requirements NIST SP 800-171 R2 enumerates
(110 in total), the `coverageNote` names 800-171, and no control carries
`requirementTextIsVerbatim` or `cmmcLevel`.

## Out of scope

- Compiling from NIST SP 800-171 Revision 3 or SP 800-172 Revision 3.
- A `ciso:scope` step for CMMC; the level chosen at register time is the scope decision.
- PCI DSS v4.0.1, abandoned mid-build on licence (see Decisions).

## Decisions

- When a regulation incorporates a standard by reference, the regulation's cited edition binds,
  even after the publisher withdraws it. 32 CFR 170.2 binds SP 800-171 R2 and SP 800-172 (Feb
  2021); compiling from the current Revision 3 would have shipped a clean, well-cited, wrong set
  (DEC-0021).
- PCI DSS was dropped because PCI SSC's terms of use prohibit derivative works. That is a
  contract constraint reaching use, which the repo's eight-consecutive-word copyright check
  cannot answer. `ADDING-A-CERTIFICATION.md` now makes checking the publisher's terms step zero.
- HIPAA Security Rule and NIST CSF 2.0 were rejected as not certifiable.
- Per-control fields that are byte-identical on every control (`citations`, `cmmcLevel`,
  `requirementTextIsVerbatim`) belong at file level; a test asserts none return, because the
  dashboard renders unknown per-control fields as detail on every card.
- Extraction was cross-checked against the standard's own Appendix D mapping tables and a second
  typesetting of the text, because a 1..n sequentiality check cannot detect a missing last child
  and `pdftotext -layout` scrambles multi-column pages.

## Deferred

- Revision 3 control sets, only when 32 CFR Part 170 is amended to cite them.
- Additional certifications, per the candidate analysis in `ADDING-A-CERTIFICATION.md`.
